# GPU 架构与存储

本章面向已经理解进程、线程和存储层次的读者。完成后，你应能画出一次模型计算从主机内存进入 GPU（图形处理器）、经过显存和计算单元、再返回结果的数据路径，并区分计算时间、显存访问时间和主机设备传输时间。

## 学习目标与前置知识

- 解释流式多处理器、线程束和单指令多线程执行的关系。
- 区分寄存器、共享内存、缓存和设备全局内存的作用范围。
- 解释 CUDA 流的顺序语义，以及多流并不保证并发执行。
- 先掌握[操作系统与资源定位](../01-computer-systems/01-os-and-resources.md)中的线程与内存概念。

## 从线程到流式多处理器

以下术语采用 NVIDIA CUDA（英伟达统一计算设备架构）的编程模型。其他厂商的 GPU 有相似目标，但执行宽度、命名和存储结构不一定相同。

NVIDIA GPU 由多个流式多处理器（Streaming Multiprocessor，SM）组成。程序启动内核时，把工作组织为网格、线程块和线程。SM 接收线程块，并以线程束（Warp）为基本调度分组。CUDA 编程指南说明，一个线程束包含 32 个线程；同一线程束通常执行共同指令，但每个线程仍保存自己的执行状态。详见 [CUDA 单指令多线程执行模型](https://docs.nvidia.com/cuda/cuda-programming-guide/03-advanced/advanced-kernel-programming.html#simt-execution-model)。

当线程束内的线程因数据条件走向不同分支时，硬件需要分别执行相关路径，并屏蔽不参与该路径的线程。分支发散可能降低利用效率，但实际影响取决于架构、分支分布和其他瓶颈。不能只凭代码里出现 `if` 就判断性能一定很差。

SM 内含算术执行资源、寄存器、调度资源和片上存储。矩阵乘法可能使用面向矩阵运算的专用单元；具体支持的数据类型、指令和吞吐随 GPU 架构变化。分析时应查目标设备与软件版本，不要把某一代硬件数字当成通用属性。

## 存储层次与数据生命周期

从逻辑作用看，可先使用以下层次：

| 层次 | 常见作用范围 | 主要特点 |
| --- | --- | --- |
| 寄存器 | 单线程 | 容量小、靠近执行单元；过多使用可能限制并行驻留 |
| 共享内存 | 同一线程块 | 由程序显式协作使用；适合复用和线程间交换 |
| L1/L2 缓存 | SM 或整个设备 | 自动缓存部分访问；命中行为取决于访问模式和架构 |
| 设备全局内存 | 整个 GPU | 容量大，模型权重、激活和 KV Cache（键值缓存）通常驻留于此 |
| 主机内存 | CPU（中央处理器）侧 | 与设备内存之间的数据移动经过主机设备互联 |

数据在显存中不代表计算单元能立即获得它。访问合并、缓存命中、数据布局、复用和同步都会影响有效带宽。NVIDIA 的 [CUDA 最佳实践指南](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#bandwidth)建议分别看理论带宽和由实际读写量及时间计算出的有效带宽。

高带宽显存（High Bandwidth Memory，HBM）描述一种高带宽设备内存技术，但“HBM”本身不能说明具体容量、带宽或访问效率。应使用目标设备规格和实测结果。

## 主机与设备之间的数据路径

模型服务可能包含以下数据移动：

```text
存储或网络
    ↓
主机内存
    ↓  PCIe 或其他主机设备互联
GPU 设备内存
    ↓
缓存、共享内存、寄存器
    ↓
计算单元
```

PCI Express（高速串行计算机扩展总线，PCIe）常用于 CPU 与 GPU、网卡与 GPU 之间的连接。NVLink（英伟达高速互联）可用于部分 GPU 和系统组件之间的高速连接。实际路径可能经过交换芯片、多个非统一内存访问节点或网络接口，因此链路标称带宽不能直接代表端到端有效带宽。

如果模型权重频繁在主机与设备之间搬运，传输时间可能大于单次计算时间。容量规划需要先说明数据是否长期驻留、何时复制、是否与计算重叠。

## CUDA 流与异步执行

CUDA 流是按顺序提交操作的工作队列。同一流中的内存复制和内核启动按入队顺序执行。多个流可以同时有待处理工作，但能否实际重叠取决于硬件能力、资源占用、依赖和同步。流的优先级也是调度提示，不保证指定执行顺序。详见 [CUDA 异步执行文档](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html)。

测量异步程序时，主机端的内核启动返回时间不等于设备完成时间。必须在正确的同步点或使用设备事件计时，否则可能只测到排队开销。

## 估算主机设备传输下界

运行课程的 Roofline（屋顶线性能模型）估算器：

```bash
python3 examples/roofline_estimator.py
```

默认教学假设中，需要通过一条 `64 GB/s` 的理想链路传输 `14 GB` 数据，因此：

`14 GB ÷ 64 GB/s × 1000 = 218.75 ms`

把链路带宽改为 `32 GB/s`：

```bash
python3 examples/roofline_estimator.py --link-bandwidth-gb-s 32
```

理想传输时间应变为 `437.5 ms`。这里的 `GB` 是十进制单位，即 `10⁹` 字节。结果不含协议、分包、方向竞争、固定延迟、同步、拓扑绕行或其他流量，不能作为 PCIe 或 NVLink 的实际性能结论。

## 验收标准

- 能画出主机内存、设备内存、片上存储和计算单元之间的数据路径。
- 能解释线程、线程束和 SM 的关系，并说明术语的厂商范围。
- 能解释为什么多条 CUDA 流不保证操作一定重叠。
- 能复现 `218.75 ms` 和 `437.5 ms` 两个理论传输下界。
- 能列出至少四项导致有效带宽低于标称带宽的因素。
