# 张量计算与自动微分

本章面向能阅读 Python（编程语言）代码、了解基础线性代数的读者。完成后，你应能沿着张量形状追踪一次前向计算，并解释训练为什么需要保存计算图和中间结果、推理为什么通常不需要反向传播。

## 学习目标与前置知识

- 用形状描述批量、序列、隐藏维度和输出维度。
- 区分参数、输入、中间激活和梯度的生命周期。
- 解释反向模式自动微分如何沿计算图累积梯度。
- 先掌握 Python 基本语法、向量、矩阵和导数的基本含义。

## 用形状阅读张量程序

张量是带有多个维度的数值数组。对大语言模型常见的隐藏状态，可用 `[B, S, H]` 表示：

- `B`：批量中的序列数量。
- `S`：每条序列的词元数量。
- `H`：每个词元的隐藏维度。

假设输入 `X` 的形状为 `[B, S, H]`，线性层权重 `W` 的形状为 `[H, O]`，矩阵乘法 `X @ W` 的输出形状是 `[B, S, O]`。矩阵乘法只要求相乘的内部维度 `H` 相同；批量和序列维度被保留。PyTorch 的 [`torch.matmul` 文档](https://docs.pytorch.org/docs/stable/generated/torch.matmul.html)列出了不同维数输入的处理规则。

追踪模型时，先记录每一步的输入形状、输出形状、元素类型和设备位置。许多报错和资源异常都可归结为以下问题：

- 形状不兼容，导致计算无法执行或发生意外广播。
- 维度顺序错误，导致语义与预期不同。
- 元素类型变化，导致精度、存储量或可用算子发生变化。
- 张量跨设备移动，产生额外复制和等待。

## 参数、激活与梯度

以下对象的生命周期不同：

| 对象 | 来源 | 训练时 | 推理时 |
| --- | --- | --- | --- |
| 模型参数 | 训练得到的权重 | 前向、反向和更新都要使用 | 前向计算使用 |
| 输入 | 数据或请求 | 进入前向计算 | 进入前向计算 |
| 中间激活 | 每层前向输出 | 反向传播可能需要，因此常需保留或重算 | 下游层使用后通常可释放或复用空间 |
| 梯度 | 损失对参数或中间值的导数 | 反向传播生成并用于更新 | 常规推理通常不生成 |
| 优化器状态 | 优化算法维护的状态 | 参数更新使用 | 常规推理不需要 |

具体框架可能使用检查点重算、内存复用、算子融合或编译优化改变实际生命周期。表格描述的是逻辑角色，不是所有实现的精确内存行为。

## 计算图与反向模式自动微分

前向计算把输入和参数连接成一张有向计算图。每个运算知道自己的输入以及局部导数。反向传播从标量损失开始，按与前向相反的依赖顺序应用链式法则。

如果一个值通过多条路径影响最终结果，各条路径产生的梯度需要累加。PyTorch 的[自动微分机制文档](https://docs.pytorch.org/docs/stable/notes/autograd)把自动微分系统描述为反向模式自动微分；框架会按运算需要保存反向计算所需的值。

以 `loss = (x × weight + bias)²` 为例，令 `x = 2`、`weight = 3`、`bias = 1`：

- 前向结果 `prediction = 7`，`loss = 49`。
- `∂loss/∂x = 2 × 7 × 3 = 42`。
- `∂loss/∂weight = 2 × 7 × 2 = 28`。
- `∂loss/∂bias = 2 × 7 = 14`。

## 运行自动微分实验

仓库提供一个只处理标量的教学实现。它用拓扑顺序执行反向传播，不依赖第三方库。在仓库根目录运行：

```bash
python3 examples/toy_autograd.py
```

输出中的 `prediction` 应为 `7.0`，`loss` 应为 `49.0`，三个梯度应分别为 `42.0`、`28.0` 和 `14.0`。

运行自动检查：

```bash
python3 -m unittest tests.test_toy_autograd -v
```

第二项检查构造 `value × value + value`。同一个值通过三条局部路径影响结果，梯度必须累加为 `2 × value + 1`；当 `value = 3` 时结果为 `7`。

## 实验边界

教学实现不包含张量、广播、原地修改、设备执行、混合精度、高阶导数或并行计算。它只能解释计算图、链式法则和梯度累加，不能用于训练模型或评估 PyTorch 性能。要学习框架接口，请继续阅读 [PyTorch 自动微分教程](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial)。
