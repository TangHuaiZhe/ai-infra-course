# 精度与 KV 缓存

本章面向准备做推理容量规划的读者。完成后，你应能从参数量、元素字节数、模型层数、键值头数、头维度和活跃词元数估算权重与键值缓存（KV Cache）的基础存储量，并指出估算与实际显存之间的差异。

## 学习目标与前置知识

- 区分数值格式、存储字节数和计算精度。
- 估算模型权重和 KV 缓存的理论大小。
- 解释上下文长度、并发序列数和 KV 头数如何影响缓存容量。
- 先完成[Transformer 与注意力](02-transformer-and-attention.md)。

## 数值格式不是一个单独旋钮

常见格式包括 FP32（32 位浮点数）、FP16（16 位浮点数）、BF16（脑浮点 16 位）、FP8（8 位浮点数）和 INT8（8 位整数）。位宽影响单个元素的基础存储量，但实际计算还涉及：

- 算子是否支持该格式。
- 输入、权重、累加和输出分别使用什么格式。
- 是否需要缩放因子、零点或其他量化元数据。
- 硬件对该格式的吞吐、带宽和转换支持。
- 降低精度后，模型质量和数值稳定性是否仍满足要求。

因此，“位宽减半”不保证整个服务显存减半、速度翻倍或输出质量不变。PyTorch 的[数值精度说明](https://docs.pytorch.org/docs/stable/notes/numerical_accuracy.html)也指出，浮点运算顺序、后端和降低精度的归约设置都会影响数值结果。

## 权重大小估算

最基础的权重存储估算是：

`权重字节数 ≈ 参数数量 × 每个权重的字节数`

课程估算器默认使用 `70 亿` 个参数和每个权重 `2 字节`：

`7,000,000,000 × 2 = 14,000,000,000 字节 ≈ 13.04 GiB`

这里的“十亿”使用十进制，`GiB` 使用二进制，即 `1 GiB = 1024³ 字节`。结果不含量化元数据、张量对齐、加载时副本、运行时缓冲、激活、KV 缓存和分布式通信空间。

## KV 缓存大小估算

对于键和值都使用固定形状的简化模型：

`KV 字节数 ≈ 2 × 层数 × 活跃词元总数 × KV 头数 × 每头维度 × 每元素字节数`

其中：

- 前面的 `2` 分别代表键和值。
- 活跃词元总数是所有活跃序列已占用的缓存词元之和。
- KV 头数可能等于查询头数，也可能因多查询或分组查询结构而更少。

默认教学配置使用 32 层、4 条序列、每条 4096 个词元、32 个 KV 头、头维度 128、每个缓存元素 2 字节。理论 KV 缓存为：

`2 × 32 × (4 × 4096) × 32 × 128 × 2 = 8 GiB`

这只计算已填充词元对应的键和值，不包含分块后的空余位置、页表或块表、分配器碎片、缓存驱逐结构、通信副本和框架开销。

## 运行资源估算实验

运行默认配置：

```bash
python3 examples/model_memory_estimator.py
```

关键结果应为：

- 权重约 `13.04 GiB`。
- KV 缓存 `8 GiB`。
- 单层完整注意力分数矩阵如果物化则为 `4 GiB`。

将 KV 头数从 32 改为 8：

```bash
python3 examples/model_memory_estimator.py --kv-heads 8
```

KV 缓存估算应从 `8 GiB` 降为 `2 GiB`，因为公式中的 KV 头数降为四分之一。概念注意力分数元素数保持不变，因为本估算仍使用 32 个查询头。

将活跃序列数量从 4 改为 16：

```bash
python3 examples/model_memory_estimator.py --sequences 16
```

KV 缓存估算应增长到 `32 GiB`。这验证线性容量关系，不代表引擎一定能在给定显存中接纳对应并发，也不包含批处理和分块效率。

## 把估算迁移到真实模型

1. 从模型配置读取层数、查询头数、KV 头数和每头维度。
2. 明确权重与 KV 缓存分别使用的数据类型。
3. 根据真实请求分布统计活跃序列长度，不要只使用最大上下文长度。
4. 记录引擎版本、缓存块大小、显存利用率设置和并行策略。
5. 将纸面估算与运行时指标对照，分析权重、缓存、临时区和框架开销之间的差额。

如果模型使用滑动窗口、跨层共享、混合注意力、缓存压缩或跨设备分片，应修改公式，而不是把默认公式强行套用。

## 验收标准

- 能解释格式位宽、存储大小与计算精度之间的区别。
- 能复算 `13.04 GiB` 权重和 `8 GiB` KV 缓存示例。
- 能解释 KV 头数、并发序列数和上下文长度如何进入公式。
- 能复现 `8 个 KV 头 → 2 GiB`、`16 条序列 → 32 GiB` 两组结果。
- 能列出至少五项估算未包含的实际显存开销或实现差异。
