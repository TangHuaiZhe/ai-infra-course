# Transformer 与注意力

本章面向已经能追踪张量形状的读者。完成后，你应能把 Transformer（变换器模型）的一层拆成注意力和前馈计算，写出注意力主要张量的形状，并解释输入长度为何影响预填充的计算与中间数据规模。

## 学习目标与前置知识

- 追踪查询、键、值和注意力分数的形状。
- 区分预填充与逐词元解码中的注意力形态。
- 区分概念上的注意力分数矩阵与实际显存分配。
- 先完成[张量计算与自动微分](01-tensors-and-autograd.md)。

## Transformer 层的逻辑结构

原始 Transformer 架构由注意力、逐位置前馈网络、残差连接和归一化等组件组成，详见论文 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)。后续模型对归一化位置、激活函数、位置表示、注意力头和前馈结构做了大量改变。因此，分析具体模型时，应以模型配置和实现为准。

对推理基础设施而言，先抓住两条主要数据路径：

1. **注意力路径**：隐藏状态投影为查询（Query）、键（Key）和值（Value），计算相关性，再汇总值。
2. **前馈路径**：每个词元独立经过线性变换和非线性计算，部分架构使用稀疏激活的混合专家模型（Mixture of Experts，MoE）。

残差连接把子层输出与输入相加。归一化帮助控制数值尺度。不同组件消耗计算、显存和内存带宽的方式不同，不能只用“参数量”推断运行瓶颈。

## 缩放点积注意力

单个注意力头的核心计算可写为：

`Attention(Q, K, V) = softmax(QKᵀ / √d) V`

其中 `d` 是每个头的维度。缩放、掩码和数值稳定处理会影响实际实现；此公式只展示主要数据依赖。

对批量 `B`、序列长度 `S`、查询头数 `A`、每头维度 `D`，预填充阶段的概念形状可写为：

| 张量 | 概念形状 | 含义 |
| --- | --- | --- |
| 查询 `Q` | `[B, A, S, D]` | 每个位置发出的查询 |
| 键 `K` | `[B, K, S, D]` | 被查询的键；`K` 是 KV 头数 |
| 值 `V` | `[B, K, S, D]` | 与键对应的值 |
| 注意力分数 | `[B, A, S, S]` | 每个查询位置与可见键位置的关系 |
| 注意力输出 | `[B, A, S, D]` | 对值的加权汇总 |

标准多头注意力中常有 `K = A`。分组查询注意力可以让多个查询头共享较少的键和值头。具体实现如何展开或广播这些头，应以算子实现为准。

自回归模型使用因果掩码，阻止当前位置读取未来词元。掩码改变哪些位置可见，但概念上的方形分数关系仍随 `S²` 增长。现代融合注意力算子可能分块计算而不把完整 `[B, A, S, S]` 矩阵写入显存，因此**概念矩阵大小不是实际显存占用**。

## 预填充与解码

在预填充阶段，模型同时处理输入上下文中的多个查询位置。对完整注意力，概念分数元素数与 `S²` 成正比。

在逐词元解码阶段，每一步通常只有一个新查询位置，但需要读取已有键和值。单步概念分数形状更接近 `[B, A, 1, S]`。随着上下文增长，每一步需要读取的历史状态也增长。实际瓶颈还取决于批量、模型结构、数据类型、缓存布局、硬件和内核实现。

## 估算概念注意力规模

运行课程的资源估算器：

```bash
python3 examples/model_memory_estimator.py
```

默认教学配置是 4 条序列、每条 4096 个词元、32 个查询头，并假设每个分数元素占 2 字节。输出中的：

```text
attention_scores_gib_per_layer_if_materialized = 4.0
```

表示单层完整分数矩阵如果全部物化，需要约 `4 GiB`。这不是实际引擎显存测量。

把序列长度减半：

```bash
python3 examples/model_memory_estimator.py --tokens-per-sequence 2048
```

对应结果应为 `1 GiB`，即原来的四分之一。这个变化验证的是 `S²` 关系，不代表端到端延迟也会严格按四倍变化。

## 验收标准

- 能从 `Q` 和 `K` 的形状推出注意力分数形状。
- 能解释因果掩码解决什么问题。
- 能区分预填充的 `[S, S]` 关系与单步解码的 `[1, S]` 关系。
- 能复现 `4096 → 4 GiB`、`2048 → 1 GiB` 的教学估算。
- 能说明为什么概念分数矩阵不能直接当作真实显存占用或延迟预测。
