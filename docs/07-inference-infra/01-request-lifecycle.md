# 请求生命周期

本章面向有后端开发经验的读者。读完后，你应能把一次流式大模型请求拆成可测量的阶段，并判断客户端延迟包含哪些环节。

## 学习目标与前置知识

- 画出从请求进入服务到最后一个输出词元（Token）的时间线。
- 区分预填充（Prefill）、解码（Decode）、排队和网络传输。
- 先掌握[Transformer 与注意力](../04-deep-learning-compute/02-transformer-and-attention.md)及[并发与网络](../01-computer-systems/02-concurrency-and-network.md)的基本概念。

## 一次请求发生了什么

1. **接入与排队**：网关接收请求并完成鉴权、路由；引擎可能等待计算或显存资源。
2. **输入准备**：服务将文本转换为词元，构造模型输入；部分实现还会查找缓存。
3. **预填充**：模型处理输入词元，生成后续解码所需的内部状态，包括键值缓存（KV Cache）。
4. **解码**：模型逐步生成词元，每一步读取历史状态并更新缓存。采样与输出处理也会耗时。
5. **传输与结束**：服务把内容发送给客户端，并在完成或取消时释放资源。

这些阶段不一定能从客户端时间戳中分离。客户端测得的“发出请求到首个流式片段”包含网络、排队、输入处理、预填充及传输。引擎内部指标可能提供更细的拆分，但定义随实现和版本变化。**首词元延迟不能直接等同于预填充耗时。**

## 三个时间指标

设请求发送时间为 `t0`，收到第一个输出词元的时间为 `t1`，收到最后一个输出词元的时间为 `tn`，输出词元数为 `n`：

| 指标 | 本课程采用的定义 |
| --- | --- |
| 首词元延迟（Time to First Token，TTFT） | `t1 - t0` |
| 端到端延迟（End-to-End Latency，E2E） | `tn - t0` |
| 每输出词元平均间隔（Time Per Output Token，TPOT） | `n > 1` 时为 `(tn - t1) / (n - 1)`；`n = 1` 时不定义 |

这个 TPOT 公式与 [vLLM 服务基准文档](https://docs.vllm.ai/en/latest/benchmarking/cli/)一致，但不同工具的聚合方式可能不同。流式片段也不一定严格对应一个词元，因此记录时应写明数据来源。

## 动手实验：标注请求时间线

打开仓库中的[教学用模拟请求记录](https://github.com/TangHuaiZhe/ai-infra-course/blob/main/examples/sample_trace.csv)。三个时间字段使用同一原点，**不是实际模型测量值**。

1. 对 `r1` 计算 TTFT、E2E 和 TPOT。
2. 找出 TTFT 最大的请求，列出可能原因；仅凭此记录无法确定真实原因。
3. 为真实服务设计采集点：客户端发送、网关接收、入队、出队、预填充结束和最后输出。说明跨机器时钟偏差可能造成什么问题。

`r1` 应得到 TTFT `100 ms`、E2E `300 ms`、TPOT `50 ms`。这些数值只用于核对公式。

## 验收标准

- 能画出排队、预填充、解码和传输的时间线，并指出客户端无法直接观测的阶段。
- 能解释 TTFT 为什么不能单独证明预填充慢。
- 能复算 `r1`，并指出单个输出词元的 TPOT 未定义。
